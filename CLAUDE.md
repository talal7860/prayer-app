# Adhan App (prayer-app)

React Native prayer-times app (TypeScript). Shows daily prayer times from the device
location, lets the user pick calculation methods, and schedules a local notification
(optionally with the Makkah azan) for each prayer.

## Stack

- **Expo SDK 58** → React Native **0.88.1**, React **19.3.0**. New Architecture only
  (the legacy architecture was removed in RN 0.82).
- **Continuous Native Generation**: `ios/` and `android/` are generated by
  `npx expo prebuild` and are git-ignored. Never hand-edit them. Change `app.json`
  (or add a config plugin) and re-run prebuild.
- Navigation: React Navigation 7 (`native-stack` + `bottom-tabs`), see `App.tsx`.
- Notifications: `expo-notifications` (`index.js` handler, `app/hooks/usePushNotifications.ts`,
  `app/lib/notifications.ts`), kept topped up by `expo-background-task` (`app/backgroundTask.ts`).
- Location: `expo-location` (`app/screens/SettingsScreen/Location/index.tsx`).
- Storage: `@react-native-async-storage/async-storage` 2.x (Expo-pinned, not 3.x).
- i18n: `i18n-js` v4 (`app/I18n.ts`). **English, Arabic and Urdu** (`app/locales/{en,ar,ur}.json`),
  picked from the phone's preferred languages with `expo-localization`. A test keeps the keys and
  `{{placeholders}}` of all three in sync: add every new string to all three files.
  - Right to left: `app.json` → `extra.supportsRTL` plus native `locales`
    (`app/locales/native/*.json`: app name, permission prompts) make iOS/Android mirror the layout
    when the phone is in Arabic or Urdu. Use `start`/`end` thinking; RN swaps left/right styles.
    `Icon` mirrors `chevron`/`back` in RTL.
  - Dates go through `dateLocale()` (`<lang>-u-nu-latn`: localized names, Latin digits).
    AM/PM is `time.am`/`time.pm`. Method names and city names stay as they are.
- Prayer-time math: the **`adhan`** library (`app/lib/prayerTimes.ts`). It replaced the vendored
  `PrayTimes.js` (Nov 2026); times moved by ≤ 1 min (Asr ≤ 2 min). The saved method keys are
  still PrayTimes' (`MWL`, `ISNA`, `Egypt`, `Makkah`, `Karachi`, `Tehran`, `Jafari`) and map to
  adhan presets (`Jafari` = custom 16°/14°/maghrib 4°). `PolarCircleResolution.AqrabBalad` keeps
  Arctic summers valid.
- Global types live in `app/types/main.d.ts` (ambient, no imports).

## App structure (redesign)

The UI follows the "Adhan App Redesign" canvas: https://claude.ai/artifact/TzzomF9PAhGP8cMVuSz2NK
(epic #21).

- `App.tsx`: loads Inter, waits for the saved settings (`loaded`), then a root stack over
  bottom tabs `today` / `qibla` / `week` / `settings`, plus `location`, `method`, `highLats`, `sound`.
  `usePushNotifications()` is mounted once here.
- **First-run setup** (`app/screens/SetupScreen`): while `settings.onboarded` is false the
  stack has only `setup`. It asks for location (GPS via `useLocate`, or a typed city through
  `geocodeAsync`), method, Asr, and the high-latitude rule (only at |lat| ≥ 48°), then shows
  today's times. Method and Asr are preselected from the country (`app/lib/recommend.ts`).
  Nothing is saved until Start. Saved settings without `onboarded` (installs from before the
  setup) count as done (`parseSettings`). The notification permission prompt waits for it.
- **Notification scheduling**: `rescheduleNotifications(settings)` (`app/lib/notifications.ts`)
  cancels everything and schedules `fillSchedule` from `app/lib/schedule.ts`: as many prayers
  as fit under iOS's **64 pending notifications** (about 12 days, planned from 14), plus one
  last "Open Adhan App…" reminder just after them. It runs on settings changes, at day
  change, on every foreground, and from the background task (`expo-background-task`, at most
  every 12 h, reading settings from AsyncStorage via `loadSettings`). Calls are queued so they
  never interleave.
  Each notification has a fixed id (`notificationId`: kind, prayer, minute), and after scheduling
  any pending notification not in the plan is cancelled, so overlapping runs can't leave two
  copies of a prayer (seen on an iPhone: the same adhan a minute early and on time). Before this, only 5 days were scheduled and only while the app was open,
  so notifications stopped if it wasn't opened for 5 days.
  Background tasks **don't run on the iOS simulator**; test on a device (or Android).
- Pure, React-free modules (usable from the background task): `app/lib/prayerTimes.ts`
  (`prayerTimesFor(settings, date)`, `methodName`), `app/lib/settingsStore.ts` (defaults,
  `parseSettings`, `loadSettings`). The settings context wraps them.
- `app/theme/tokens.ts`: light/dark palettes, per-period sky gradients, Inter font names.
  Use these instead of hex values in screens.
- `app/components/ui/`: `Text` (Inter, pick the weight with `weight`, not `fontWeight`),
  `Icon` (the design's stroke SVGs), `Card`/`Row`/`SectionLabel`, `Segmented`, `Toggle`, `ChoiceList`.
- `app/lib/prayerDay.ts`: pure helpers (period of day, next prayer, countdown, sun arc,
  time format, Hijri date, distance). `app/lib/schedule.ts`: which notifications to
  schedule. Both are unit-tested in `__tests__/`. Keep logic there, not in screens.
- `app/hooks/usePrayerDay.ts`: yesterday/today/tomorrow times, ticking every second.
- `useTravelCheck`: on foreground, if location permission is **already** granted and today's
  prayer times where the device is differ from the saved location's by **≥ 2 minutes**
  (`movedEnough` in `app/lib/travel.ts`), Today shows the travel banner. It never prompts.
- **Travel alerts** (opt-in, Settings → Location), "Always" location. `checkTravel`
  (`app/travelTask.ts`) posts "You're in {city}" when the times differ by ≥ 2 min, once per new
  place (`@prayer_app:travelNotifiedAt`); opening the app shows the banner.
  - iOS: a 25 km geofence (`startGeofencingAsync`) on the saved location wakes the app.
  - Android: **coarse location only** (`ACCESS_FINE_LOCATION` and `FOREGROUND_SERVICE_LOCATION`
    are in `blockedPermissions`; city-level is enough for prayer times). Geofencing needs fine
    location, so the background task (~every 12 h) runs `checkTravel` instead.
- **Qibla finder** (#38): the `qibla` bottom tab (it was a stack screen behind a compass button in
  Today's top bar; moved to a tab on request). It's mounted only while its tab is focused
  (`QiblaTab` in `App.tsx`), so the compass stops when you switch tabs.
  **Recalibrate compass** (`useHeading().recalibrate`) drops the last reading, resubscribes and
  shows the figure-8 steps for 15 s (`CALIBRATE_FOR_MS`), even if the phone reports good accuracy. `app/lib/qibla.ts` (pure, tested): adhan's `Qibla()` bearing from
  true north for `settings.location`, distance to the Kaaba, offset/`unwrap` (the dial turns the short
  way across north), facing within ±5° (stops past ±8°). `useHeading` wraps
  `watchHeadingAsync` (`trueHeading`, else `magHeading` when it's −1); location permission only, it
  never prompts unless "Allow location" is tapped. `accuracy` ≤ 1 shows a calibrate hint; no reading in
  4 s (simulator) shows "No compass". The dial is Views + rotate transforms, and it's geographic, so it
  doesn't mirror in RTL. A light `expo-haptics` tap when it turns to facing (once each time).
- **Adjust times** (Settings → Calculation): per-prayer ± minutes (`settings.adjustments`,
  ±30), adhan's `params.adjustments` in `prayerTimesFor` (on top of the method's own).
- `useCityName` fills `settings.city` by reverse geocoding when it's missing.
- Settings model (`Settings` in `main.d.ts`): `muted` (per-prayer bells; Sunrise has no bell,
  isn't in Today's list and is never notified: it's on the sun arc), `headsUp` (extra notification 10 min before), `timeFormat`, `city`, `highLats`
  (`NightMiddle` default / `AngleBased` / `OneSeventh`), `onboarded`, `adjustments`,
  `travelAlerts`, `liveActivity`.
- During Fajr the countdown is to sunrise and reads **"Fajr ends in"** (`today.endsIn`), on Today,
  in the widgets (`inLabel`, `untilLabel` → `widget.untilEnd`) and the Live Activity.
- Far north in summer Isha can be after midnight (Calgary, June, Karachi: 01:38).
  adhan returns real instants, so that Isha is already on the next calendar day.
- Times are always shown in the phone's timezone, even for a searched city elsewhere.
- Fajr and Isha always come from the calculation method's angles. The old
  `fajrIshaCalculation: '90mins'` rule (Fajr = sunrise − 90 min, Isha = maghrib + 90 min,
  patched into the old `PrayTimes.js`) was **removed on purpose**; a saved value is dropped on load.
  Don't re-add a 90-minute option (the design's "Isha 18° / 90 min" control was dropped too).
- **Apple Watch app** (#35, the canvas's "Apple Watch" board), via `@bacons/apple-targets`
  (`ios/` stays generated):
  - `targets/watch/` (SwiftUI app `AdhanWatch`, `com.conelabs.adhanapp.watchkitapp`): countdown home
    (arc Fajr → Isha filled to now, dots per prayer) and, on the next vertical page, today's list.
  - `targets/watch-widget/` (`AdhanComplications`, `….watchkitapp.complications`): circular ring,
    rectangular with a progress bar, inline, corner. Timeline: every prayer + every 15 min, 24 h.
  - `targets/_shared/` is compiled into every target: `Adhan/` is **adhan-swift, vendored** (no
    SPM support; same library as the phone's `adhan`, so times match) and `PrayerCore.swift`
    (settings model, the same method mapping as `prayerTimes.ts`, `PrayerSnapshot`, colours).
  - Settings reach the watch over WatchConnectivity: `syncWatch` (`app/lib/watch.ts`, on every
    settings change) → local Expo module `modules/watch-sync` (`updateApplicationContext`) →
    `PhoneLink` on the watch saves them in the App Group and reloads the complications. Labels
    (prayer names, "until %@") are sent in the phone's language. Without settings the watch
    asks you to open the phone app.
  - Compile check without a watch simulator: `xcodebuild -workspace ios/AdhanApp.xcworkspace
    -scheme AdhanWatch -destination 'generic/platform=watchOS Simulator' CODE_SIGNING_ALLOWED=NO build`.
    Big SwiftUI closures can time out the Swift type checker ("failed to produce diagnostic"):
    split them into small views/functions.
  - Running it in the simulator: the watchOS runtime pairs only with the same-generation iOS
    runtime (watchOS 27 ↔ iOS 27). `xcrun simctl create` an iPhone and a watch, `simctl pair`
    them, build the `AdhanWatch` scheme for the watch's id and `simctl install` the `.app`.
    To skip the phone, write settings straight into the App Group:
    `xcrun simctl spawn <watch> defaults write group.com.conelabs.adhanapp watchSettings -string '<json>'`
    (the shape `watchPayload` sends). To test the real sync, build `AdhanApp` (Release bundles
    the JS), install it on the iPhone, then install its `Watch/AdhanWatch.app` on the watch (the
    phone doesn't install it by itself here) and relaunch the watch app. `WatchLink` keeps the
    latest settings and resends them when the watch app gets installed (`sessionWatchStateDidChange`).
    An unsigned build has no App Group, so `simctl spawn … defaults read` won't see what the app
    saved; check the screen. Complications: add the rectangular one from the Smart Stack
    (swipe up on the face → Edit → + → Adhan); most faces in the simulator have no free slots.
  - Files in `targets/_shared` other than Swift sources get copied into every bundle, which is why
    the vendored library's licence is a comment-only `Adhan/LICENSE.swift`.
  - EAS signs two more bundle ids; the first build after adding them needs an interactive
    `eas build -p ios` (or `eas credentials`) to create their profiles.
- **Monthly timetable** (Week → "Share the {month} timetable"): `app/lib/timetable.ts` builds an
  A4 HTML page (RTL-aware), `expo-print` makes the PDF, `expo-sharing` opens the share sheet.
- `getPrayerTimes(date)` computes that date (it used to ignore `date`), and labels Friday's
  Dhuhr "Jumu’ah".
- **Widgets and Live Activity** (`expo-widgets` + `@expo/ui`, #20):
  - Design: the canvas's "Widgets & lock screen" board (#34). Two widgets in the gallery:
    `NextPrayer.ios.tsx` ("Next prayer": sky small, medium with arc + chips, large with arc +
    list, lock screen rectangular with a progress bar, inline) and `PrayerRing.ios.tsx` ("Prayer
    ring": dark small with a gold ring, lock screen circle). `NextPrayer.android.tsx` is the
    Compose version (sky colour, next prayer, chips; no ticking or rings on Android).
    `PrayerActivity.ios.tsx` is the Live Activity / Dynamic Island countdown.
  - The plain `.tsx` files are no-op stand-ins for Jest and other platforms. **Keep them `.tsx`**:
    Metro tries every `.ts` candidate (plain included) before any `.tsx`, so a `NextPrayer.ts`
    shadows `NextPrayer.ios.tsx` and the widgets stay blank.
  - Drawing tricks (no custom paths in `@expo/ui`): the dotted sun arc is small `Circle`s placed
    with `offset` in a `ZStack`. Rings are a clear `Circle` with
    `strokeBorder({shape: 'circle', dash: [fraction × circumference, circumference]})` rotated
    −90° (`strokeBorder` defaults to a rectangle, and a `Circle` fills itself). A timer `Text`
    takes the full width: centre it with `multilineTextAlignment('center')`.
  - The widget gallery caches previews; add the widget to the home screen to see a change.
  - A layout function has the `'widget'` directive and runs in the widget's **own JS runtime**:
    no hooks, no app imports, no module-level values. Only `@expo/ui` components/modifiers
    (globals there). Pass everything already formatted through props (`app/widgets/types.ts`).
  - Data: `app/lib/widgetData.ts` (pure, tested): next prayer, its progress range (`prevAt` →
    `at`), the period's sky (`WIDGET_SKIES`), the sun and prayers on the arc, and the five
    prayers (no Sunrise in lists). iOS gets a 2-day timeline: an entry at every prayer time and
    every half hour (so the sun and ring move), with a live `dateStyle="timer"` countdown.
    Android widgets can't tick or take a timeline: it's a snapshot.
  - `refreshWidgets` runs with the notification reschedule (settings change, day change,
    foreground) and from the background task. `syncLiveActivity` starts / updates / ends the
    Live Activity in the hour before a prayer, on foreground and going to background (iOS only
    lets the app start one while it's open).
  - **Live Activity setting** (Settings → Notifications, iOS only): `settings.liveActivity`,
    **opt-in, default off** (old saved settings without it get the default). The setup's last
    step asks for it too (a switch, off, iOS only). Off makes `activityFor` return
    null, so `syncLiveActivity` never starts or updates one and ends a running one at once (the
    settings change re-runs it). One switch covers both the lock screen and the Dynamic Island:
    they're one ActivityKit activity, and iOS has no API to show it in only one of them.
  - Widget extension bundle id `com.conelabs.adhanapp.widget`, App Group
    `group.com.conelabs.adhanapp` (expo-widgets plugin options in `app.json`).
  - Jest mocks `expo-widgets` in `jest.setup.js`.
  - **Android widget countdown** (`NextPrayer.android.tsx`): Android widgets are Glance; expo-widgets
    maps no `weight`/`spaceBetween` and doesn't pass the widget size, so the layout uses `Box`
    layers and fixed-width chips. Colours are `rgba()` (RN reads `#RRGGBBAA`, not `#AARRGGBB`).
    The ticking countdown is a **`ChronometerView`**, added by `patches/expo-widgets+*.patch`
    (`patch-package`, run on `postinstall`): a RemoteViews `Chronometer` the system ticks every
    second, plus an alarm (`WidgetTicker`) that re-renders the widgets when it reaches zero. The app
    sends `androidWidgetProps` (an entry from every prayer time for two days) and the layout picks
    the entry for `Date.now()`, so the widget moves on without the app. Give the countdown and its
    column `fillMaxWidth()`, or it's clipped to the column's first width. The widget's JS is
    bundled into the APK at build time: layout changes need a native rebuild to show.
    To change the patch: edit `node_modules/expo-widgets`, then
    `npx patch-package expo-widgets --exclude '^package\.json$|android/build|android/\.cxx|\.gradle'`
    (without the exclude it picks up 1.5 MB of build output).

## Commands

```bash
yarn install
npx expo start              # Metro dev server (needs a dev build, not Expo Go, for custom sounds)
npx expo run:ios            # prebuild if needed, build and run on the iOS simulator
npx expo run:android        # same for Android
npx expo prebuild --clean   # regenerate ios/ and android/ after app.json changes
yarn typecheck              # tsc --noEmit
yarn lint                   # expo lint . --max-warnings 0 (strict, see below)
yarn format                 # prettier --write .
yarn format:check           # prettier --check . (CI)
yarn test                   # jest-expo + @testing-library/react-native
npx expo-doctor             # dependency / config health check, keep it at 20/20
```

Add or upgrade native packages with `npx expo install <pkg>` so the version matches the SDK.
For the next SDK bump: `npx expo install expo@^<next> --fix`, then `npx expo-doctor`.

**Formatting and lint**
- Prettier (`.prettierrc`): single quotes, no bracket spacing, trailing commas, `arrowParens: avoid`,
  `bracketSameLine`, width 100. `.prettierignore` skips generated native dirs, `.claude/`, the vendored
  `targets/_shared/Adhan`, lockfiles and **Markdown** (Prettier renumbers lists and re-indents code spans
  in the hand-written docs).
- ESLint (`eslint.config.js`): `eslint-config-expo` + typescript-eslint `strictTypeChecked` and
  `stylisticTypeChecked` (type-aware, `projectService`) on `.ts`/`.tsx`, then `eslint-config-prettier`.
  React hooks rules are errors. Tuned rules (each with a comment in the config): `type` over
  `interface`, arrow-shorthand void returns allowed in handlers, numbers allowed in template literals;
  in `__tests__/` the `no-unsafe-*`, `no-require-imports`, `import/first`, `no-non-null-assertion` and
  `require-await` rules are off (jest mocks).
- Inline disables need a reason (`-- why`, or a comment above).

## CI / CD

- `.github/workflows/ci.yml`: on every PR, runs typecheck, `format:check`, lint (strict, 0 warnings),
  tests and `expo-doctor`.
- `.github/workflows/deploy.yml`: **automatic deploys are currently disabled** (the `push`
  trigger is commented out). It only runs manually (Actions → Deploy → Run workflow). Once the
  one-time setup below is done, uncomment the trigger to deploy on every push to `master`.
  It re-runs CI, then one job per platform (matrix, `fail-fast: false`, so one platform failing
  doesn't hide the other) runs `eas build --platform <p> --profile production --auto-submit
  --non-interactive` on EAS. iOS goes to **TestFlight**, Android to the Play **internal testing**
  track. Releases run one at a time.
- EAS project: `@conelab-it-consultants-inc/prayer-app`. iOS builds two targets (app and the
  `ExpoWidgetsTarget` widget extension), each with its own provisioning profile. Non-interactive
  (CI) builds can't create credentials: create them once with an interactive `eas build -p ios`
  or `eas credentials -p ios` (needs the Apple ID login). An App Store Connect API key is stored
  on EAS, so non-interactive builds and submits need no Apple login, only
  `EXPO_APPLE_TEAM_ID=APPLE_TEAM_ID_REDACTED EXPO_APPLE_TEAM_TYPE=COMPANY_OR_ORGANIZATION` (set in
  `deploy.yml`; without them `--non-interactive` still prompts for the team).
- Export compliance is declared in `app.json` (`ios.config.usesNonExemptEncryption: false`), so
  neither EAS nor TestFlight asks.
- Android release builds run `lintVitalRelease`. Strings in `app/locales/native/*.json` must be
  under `"ios"` or `"android"`: top-level keys go to both, and iOS keys in Android's
  `strings.xml` fail lint (`ExtraTranslation`).
- `eas.json`: `appVersionSource: remote` + `autoIncrement`, so EAS owns the iOS build number
  and Android `versionCode`. Don't bump them in `app.json`. Bump `expo.version` for a new
  marketing version.
- Signing credentials, the App Store Connect API key and the Play service account JSON live
  in EAS (`eas credentials`), not in the repo. The only GitHub secret is `EXPO_TOKEN`.
- **Uploading by hand** (EAS Submit's free queue can take ~1 h): `scripts/upload-build.sh ios|android
  [file]` uploads to TestFlight (`xcrun altool`) or Play internal testing (fastlane
  `upload_to_play_store`). Without a file it downloads the latest finished EAS **cloud** build.
  Settings come from env vars, read from `~/.config/adhan-app/env` (outside the repo, `chmod 600`):
  `ASC_API_KEY_ID`, `ASC_API_ISSUER_ID`, `ASC_API_KEY_PATH` (the `.p8`), `PLAY_SERVICE_ACCOUNT_JSON`.
  Android needs Homebrew's `fastlane` (an rvm Ruby's can be broken).
- The workflow uses `--no-wait`: a green Action means "builds queued". Build and submit
  results are on expo.dev.

## Native config (in `app.json`)

- Display name "Adhan App" (store fallback "Adhan App: Prayer Times"). iOS bundle id and
  Android package `com.conelabs.adhanapp`, Apple team `APPLE_TEAM_ID_REDACTED` (`ios.appleTeamId`), from
  #23. Renamed from `org.personal.talal7860.PrayerTimes` / `com.talal7860.prayertimes` before
  any store release. Don't change them again once the app is in the stores.
- iOS entitlements: App Group `group.com.conelabs.adhanapp`, Time Sensitive notifications
  (adhan and heads-up use `interruptionLevel: 'timeSensitive'` to get through Focus). **No push
  entitlement**: `expo-notifications` has `enableRemoteNotifications: false` (local only).
  Background modes: fetch + processing.
- Icons and splash use the **"Arch"** concept from the design canvas's "App icon concepts"
  artboard (white pointed arch + warm sun on a `#2E63C9 → #163A85` gradient):
  - `assets/images/icon.png`: 1024², full-bleed, no rounded corners (iOS masks it).
  - Android adaptive: `adaptive-icon.png` (foreground, mark scaled to the 72/108 dp safe area),
    `adaptive-icon-background.png` (gradient), `adaptive-icon-monochrome.png` (Android 13 themed icons).
  - Splash (`expo-splash-screen` plugin): `splash-icon.png` (mark only, transparent), 120 pt wide
    on `#2453B3`, `#0D1120` in dark mode.
  - The PNGs were rendered from the design's SVG with `@resvg/resvg-js` (not a project dependency).
    To change them, edit the SVG and re-render all five at 1024², then `npx expo prebuild --clean`.
- Azan sound `assets/sounds/makkah_azan.wav` (29 s, 16-bit mono 22 kHz) is bundled by the
  `expo-notifications` plugin `sounds` option. Code refers to it by file name
  (`AppConstants.sounds.mecca.path`). **iOS notification sounds must be ≤ 30 s and
  WAV/AIFF/CAF**; the old MP3 silently fell back to the default sound. Made with
  `afconvert -f WAVE -d LEI16@22050 -c 1 in.mp3 out.wav`. Changing it on Android needs a new
  channel id (the WAV one is `adhan-makkah`; the old `prayer-time-notifications-mecca` is deleted
  on launch).
- Android permissions include `SCHEDULE_EXACT_ALARM` so prayer notifications fire on time.
  **Android 14+ doesn't grant it to new installs**: without it Android may deliver the adhan
  (and the widget's re-render alarm) tens of minutes late (`dumpsys alarm` shows `window=+38m`).
  The local module `modules/exact-alarm` (Android only) checks `canScheduleExactAlarms()` and
  opens the app's "Alarms & reminders" page. `useExactAlarms` re-checks on every foreground, and
  `ExactAlarmPrompt` asks on Today, at the end of the setup and in Settings → Notifications
  while it's off. Coming back from that page is a foreground, so `usePushNotifications`
  reschedules everything, exact this time. (Not `USE_EXACT_ALARM`: Play allows that only for
  alarm-clock and calendar apps.)
  Location is coarse only (see Travel alerts).

## Gotchas

- **React 19 types**: `React.FC` no longer includes `children`. Use
  `React.FC<React.PropsWithChildren>` or add `children` to the props interface.
- **Global `Location` type clashes with DOM's `Location`** (Expo's tsconfig includes the
  DOM lib). The app's type is `GeoLocation` in `app/types/main.d.ts`.
- **TypeScript 6 defaults `types` to `[]`**, so `tsconfig.json` lists `"types": ["jest"]`.
  Add any other global `@types/*` package there.
- **ESLint 10 breaks `eslint-plugin-react`** (`getFilename is not a function`). Stay on
  ESLint 9 until eslint-config-expo supports 10.
- **`expo lint` with no path only lints `app/`** (Expo Router's default dirs), so `yarn lint` passes `.`
  to cover `App.tsx`, `__tests__/` and `modules/` too.
- **Run Jest from a `.claude/worktrees/*` checkout** with
  `npx jest --testPathIgnorePatterns /node_modules/ --modulePathIgnorePatterns /none/`: the config
  ignores `/.claude/` paths (so the main checkout skips other worktrees), which there means every test.
- `I18n.t(...)` nested inside another `I18n.t`'s options is typed `any` (the options' index
  signature); put it in a `const` first (`no-unsafe-assignment`).
- Fire-and-forget promises in effects/handlers take `void` (`no-floating-promises`); the async
  calls are deliberately not awaited; add a `.catch` where a failure must be handled.
- `import/namespace` falsely flags `Notifications.AndroidImportance` (re-exported from a
  `.types` module); there is an inline disable for it.
- **Jest runs in `America/Edmonton`** (`jest.globalSetup.js`), the zone of the Calgary test data.
  Times are computed in the phone's zone, so without it tests that pick clock hours fail on CI
  (UTC). A city ~12 h from the phone's zone still gets mixed-up days (known limitation).
- **RNTL 14 `render` is async**: `await render(<App />)`. The App test mocks AsyncStorage,
  safe-area-context and expo-notifications (`__tests__/index.test.tsx`).
- `setSetting(key)(undefined)` keeps the old value (lodash `merge` skips undefined). To clear a
  field, use `setSettings(prev => ({...prev, key: undefined}))`.
- Settings are saved only after they've been loaded (`loaded`), so a change back to a default
  value is saved too.
- Android notification channels are immutable once created on a device. To change a
  channel's sound or importance, give it a new `channelId` in `app/AppConstants.ts`.
- iOS takes the sound from the notification content, Android from the channel; both are
  set in `scheduleNotifications`.
- For an Android channel with the system default sound, **leave `sound` out**. `sound: 'default'`
  makes expo-notifications look for a bundled file named "default". That throws, and it used to
  stop the permission request, so no notifications were scheduled at all.
- Expo SDK 58 doesn't forward `console.log` from the app to the Metro terminal (`console.error`
  still shows). If edits don't show up in the app, restart Metro with `npx expo start --clear`.
- The old "Okay" notification action (`notification.action_ok`) was dropped in the
  migration; re-adding it needs `Notifications.setNotificationCategoryAsync`.
- Custom notification sounds don't work in Expo Go. Use a dev build (`npx expo run:*`).
- `pod install` (run by `expo run:ios`) crashes with `Unicode Normalization not appropriate
  for ASCII-8BIT` if the shell locale isn't UTF-8. Run with `LANG=en_US.UTF-8`.
- `Body` uses safe-area-context's `SafeAreaView` with `edges={['left', 'right']}`. Unlike
  RN's old `SafeAreaView`, it always pads, and the header and tab bar already cover top/bottom.
